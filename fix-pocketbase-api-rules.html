🔧 Fix PocketBase API Rules - 403 Forbidden Error

This tool helps you fix the "Only superusers can perform this action" error

❌ Current Error

Error: GET /api/collections/tournaments/records 403 (Forbidden)

Message: "Only superusers can perform this action"

Cause: The API rules on your Railway PocketBase instance are too restrictive. They require superuser access when they should allow public read access.

📍 Step 1: Open PocketBase Admin Dashboard

Enter your PocketBase URL below and click the button to open the admin dashboard:

Open Admin Dashboard

🔐 Step 2: Login to Admin Dashboard

  1. If you haven't logged in yet, enter your admin email and password
  2. If you forgot your credentials, you may need to reset them via Railway console

📋 Step 3: Fix API Rules for Collections

You need to update the API rules for the following collections:

  • tournaments
  • topics
  • timer_projects
  • judges
  • matches
  • circuits
  • circuit_matches
  • registrations
  • team_members
  • judge_assignments
  • judge_scores
  • form_configs
  • ratings
  • resources
  • timers

For EACH collection, follow these steps:

  1. Click on the collection name in the left sidebar
  2. Click on the "API Rules" tab at the top
  3. Update the rules according to the table below:
Rule Type Value Description
List/Search rule (leave empty) Allows anyone to list/search records
View rule (leave empty) Allows anyone to view individual records
Create rule @request.auth.id != "" Only authenticated users can create
Update rule @request.auth.id != "" Only authenticated users can update
Delete rule @request.auth.id != "" Only authenticated users can delete
⚠️ Important: Make sure to click "Save changes" after updating each collection's API rules!

🎯 Step 4: Priority Collections (Fix These First)

If you're short on time, fix these critical collections first:

  1. tournaments - Required for displaying tournament list
  2. topics - Required for displaying debate topics
  3. registrations - Required for tournament registration
  4. judges - Required for judge listings

✅ Step 5: Verify the Fix

  1. Go back to your frontend application
  2. Refresh the page (Ctrl+F5 or Cmd+Shift+R)
  3. Check the browser console - the 403 error should be gone
  4. Tournaments should now load properly
✅ Expected Result: After fixing the API rules, your frontend should be able to:
  • ✅ List tournaments without authentication
  • ✅ View tournament details
  • ✅ Display topics and other public data
  • ✅ Allow authenticated users to create/update/delete
💡 Quick Tip: If you have many collections to fix, you can use the PocketBase Admin API or create a migration script. However, the manual method above is the safest and most reliable.

🔍 Troubleshooting

If you still see 403 errors after fixing the rules:

  1. Make sure you clicked "Save changes" for each collection
  2. Clear your browser cache and refresh
  3. Check that the rules are exactly as shown (empty for List/View, auth required for Create/Update/Delete)
  4. Verify you're logged into the correct PocketBase instance
  5. Check the browser console for any CORS errors
